# Evaluated leads (2026-09-30)

These are source-backed capability notes and our engineering assessment, not benchmark results for this corpus. No upstream scripts, trained models, or code were executed or incorporated during this audit.

- [fontTools](https://github.com/fonttools/fonttools): Python font parsing/manipulation and TTX support, MIT licensed; WOFF2 needs the Brotli extra. Strong core dependency for table metadata, names, glyph coverage, metrics, outlines, and variation axes. Parsing does not prove rendering validity or rights. Keep parsing failures and metadata conflicts visible. Current upstream main requires Python 3.11+, so pin a tested package version and document the runtime floor.
- [sliday/google-fonts-skill](https://github.com/sliday/google-fonts-skill): an MIT-licensed MCP/CLI typography generator with BM25 search over enriched tags, single-family and pairing modes, and CSS/Tailwind output. Useful interface inspiration: concise retrieval, exact lookup, and one-family choices. Its curated descriptors, suitability tiers, and pairing claims are judgments; they should not become objective metadata for these unrelated source binaries. Google Fonts embedding URLs do not resolve this local corpus.
- [tfrere/fontmap](https://github.com/tfrere/fontmap): its current README describes FontCLIP embeddings, predicted Google style tags, measured proportions, t-SNE layout, glyph sprites, and visual nearest neighbors. MIT licensed. Useful content-first comparison idea; a map is an exploration aid, not a quality or pairing score. Its font downloads, renders, embeddings, and font index are excluded from its repository, so reusing its pipeline would require substantial corpus-specific work. Source labels/title still mention UMAP while the current README describes t-SNE; follow actual implementation, not project tagline.
- [FontCLIP official implementation](https://github.com/yukistavailable/FontCLIP) and [paper](https://arxiv.org/abs/2403.06453): a typography-tuned vision-language model for semantic/image retrieval. Potential future optional search backend; it could help discover visual concepts beyond name matching. The implementation has PyTorch/model/data setup, old version constraints, and mixed MIT/noncommercial licensed sections. Retrieval cosine similarity is not suitability, legibility, or license evidence. The multilingual generalization reported in the paper has not been verified on this local corpus. For the initial harness, deterministic measured properties plus real rendered specimens are simpler to reproduce across Mac/Windows, with semantic embedding search evaluated separately before adoption.
